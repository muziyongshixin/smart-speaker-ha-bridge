# HomePod mini 控制米家，以及按房间控制

## 架构与实际结果
HomePod/Siri → Apple 家庭 → HomeKit Bridge → HA → Xiaomi Home → 米家设备。这里要添加的是 HomeKit Bridge，不是 HomeKit Device，也不是把 HomePod 作为 Apple TV 播放器加入 HA。

测试环境沿用本仓库旧手机 HA。已完成 28 个实体的配件生成和原配对保留；用户确认虚拟开关与客厅实物灯语音控制成功。房间整理后，“关闭客厅所有的灯”关闭吸顶灯、氛围灯、鱼缸灯，其他房间未受影响。不是所有配件都已单独验收。

## 1. 配对前先限制实体
HA 设置 → 设备与服务 → 添加集成 → Apple → HomeKit Bridge。先只选 Input boolean 域，确保只有测试开关；不要直接导入所有域。
HA 通知中生成配对码。用已经加入 HomePod 所在家庭的 iPhone：家庭 → + → 添加配件，扫码或手动输入当前配对码。配对码、HomeKit state 和密钥均属于私有数据，不提交仓库。

先说“嘿 Siri，打开桥接测试”，同时检查 HA 状态。仅语音回复成功不够，确认真实状态变化后再扩大实体筛选。

## 2. 扩大支持范围
在 HomeKit Bridge 选项中用明确的实体白名单添加设备，避免数百个指示灯、辅助属性和重复开关进入 Apple 家庭。本案例添加灯、空调、风扇、开关、扫地机、温湿度与两个 HA 场景。设备能力取决于 HA 实体和 HomeKit 映射，不照搬 Huawei 的开关功能边界。

配置自动化处理应优先使用 HA 支持的 UI/API。若维护旧手机时必须直接编辑存储：先备份并完全停止 HA，确认主进程退出，而不只是 HTTP 端口关闭；编辑后验证，再启动。不要删除 HomeKit 配对状态及 aids/iids 文件，正常增改筛选不需要重新配对。

## 3. Apple 家庭的房间是独立设置
HA 中有“客厅”并不意味着 Apple 家庭也自动得到该房间。请在家庭 App 新建客厅、主卧、次卧、书房，把每个配件移到实际房间。名称只保留用途：吸顶灯、空调、风扇、温度、湿度。多个房间可以各自有一个“吸顶灯”，通过房间区分。

Mac 操作：配件卡片右键 → 配件设置 → 房间；编辑顶部名称。温湿度传感器从房间顶部温度/湿度摘要进入卡片设置。保存后重新打开房间核对归属，而非只看到输入框修改就认为已完成。

HomePod 自己也必须放进真实房间。本案例是书房，而不是客厅。无房间限定的语音可能参考音箱所在房间。

## 4. 灯必须是灯
本案例四盏房间主灯由 HA switch 实体导出，最初在 Apple 家庭属于开关。配件设置 → 显示为 → 灯，才会被“关闭客厅所有的灯”包括。仅改名成“吸顶灯”不够。

客厅灯组包括吸顶灯、氛围灯、鱼缸灯。按房间关闭所有灯会包括鱼缸灯；如果想保留鱼缸照明，应另设只控制指定灯的场景，而不是假设它会自动排除。

## 5. 不同 Apple 账号的 Mac
无需退出 Mac 账号。家庭所有者可在 iPhone 家庭设置邀请 Mac 的 Apple 账户，Mac 家庭 App → 更多 → 家庭设置 → 邀请 → 接受；所有者再授权添加和编辑配件。邀请扩大了家庭控制访问，仅对你信任的账号操作。它与系统“家人共享”不是同一个功能。

## 6. 验收
1. HomePod 打开虚拟开关，HA 收到变化。
2. 单独开关真实灯，用户确认实物变化。
3. 各房间配件类别、名称、归属核对；不可用配件不伪装在线。
4. 用户说“关闭客厅所有的灯”，三盏灯关闭且卧室/书房灯不变。
5. 空调模式、温湿度问答与其他设备独立验证，不能以灯测试代替。
